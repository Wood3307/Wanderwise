# 知乎公开知识快照

`zhihu-public.json` 是在开发期间直接从知乎官方黑客松内容 API 获取的真实响应，保留了未知字段、作者和来源。获取时间见文件内 `fetchedAt`。内容归原作者及知乎所有；应用不声称原创。

来源：`https://api.zhihu.com/km-indep-home/hackathon/v2/knowledge/list` 及列表返回的 10 个 `/knowledge/{work_id}` 详情地址。参考协议见 `REFERENCE/zhihu/references/hackathon-content-api.md`。

这些接口仅供本次黑客松，当前详情大多在 3000 字处截断；界面统一标注为正文节选，不能当作完整回答。公开 API 没有提供作品的知乎问题 ID、原文网页地址或同题回答关系。公开模式按作品真实标题与正文中的关键词整理为「职场成长」「学习与行动」「心理与关系」等主题聚合；这一编辑导航明确标记 `kind: topic` 和「主题聚合」，不会把不同作品冒充同一知乎问题的回答。标题的分类权重高于正文，未匹配内容归入「知识拾遗」；列表中部分标签与正文不相符，因此不将其用作问答归属依据。

第二层展示主题下每篇真实作品的原题、作者和官方来源；第三层从实际正文中提取精华段落，保留原段落编号以供回查。查询先筛选每篇真实作品，再做主题聚合，不会因为某一作品匹配而加入同主题但不匹配的作品。默认 10 篇作品聚合为 3 个主题，每篇只出现一次。

配置知乎 Access Secret 后，非空查询使用 Skill 文档中的知乎搜索 API。第一层按照来源链接中的真实问题 ID 聚合同题回答，独立文章单独标记；进入问题时仅按该问题原题额外检索一次，最多读取 10 项，只接受相同问题 ID，或缺失问题 ID 时标题完全匹配的回答，并按来源回答 ID 去重。其他问题不会被混入；搜索缓存与问题展开缓存均为 5 分钟，相同并发请求共用一次上游请求。搜索接口提供的摘要不等于完整正文，也不保证返回某个问题的所有回答。

知乎回答在搜索接口中没有独立文章标题，回答恒星以正文中的精华原句作为显示标签，最多 60 字；知乎独立文章及公开作品保留实际原题。新的鉴权搜索在当前服务进程内串行执行，相邻请求至少间隔 1.1 秒，最多排队 4 个。这是应用侧的保守节流策略，不代表知乎规定的准确 QPS；收到频率或额度限制时停止排队中的上游调用，进入 60 秒本地冷却，不做自动重试，已有搜索缓存仍然可读。

此快照使首次启动和断网浏览可用。服务启动及探索时会在后台进行有频率限制的公开内容刷新，成功后使用内存中的最新真实内容；接口失效时保留已有快照。查询只匹配实际内容，无匹配时返回空结果。
